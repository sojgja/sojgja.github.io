Hướng dẫn Polars từ A đến Z

1. Polars là gì và tại sao nên dùng?​

Polars là thư viện DataFrame viết bằng Rust, cung cấp API cho Python, Node.js và R. Được thiết kế để xử lý dữ liệu cực nhanh nhờ:

  • Multi-threading: tận dụng tất cả CPU cores
  • Lazy evaluation: tối ưu toàn bộ query plan trước khi chạy
  • Zero-copy: tránh sao chép dữ liệu không cần thiết
  • Apache Arrow: định dạng dữ liệu columnar hiện đại
  • Out-of-core: xử lý dữ liệu lớn hơn RAM bằng streaming

So sánh benchmark (đọc CSV 100M dòng)​

OperationPandasPolars
Đọc CSV45s5s
Filter8s1s
Group by + agg12s2s
Join 2 bảng lớn30s4s

17. Lazy Evaluation - Sức Mạnh Thực Sự của Polars​

Đây là tính năng quan trọng nhất của Polars. Thay vì thực thi từng bước, Polars xây dựng một query plan, tối ưu nó, rồi mới chạy.

# Bắt đầu lazy mode
lf = df.lazy()

# Hoặc đọc file trực tiếp ở lazy mode
lf = pl.scan_csv('huge.csv')
lf = pl.scan_parquet('data/*.parquet')  # đọc thư mục parquet

# Xây dựng query plan (CHƯA chạy)
lf = (lf
    .filter(pl.col('amount') > 1000)
    .with_columns((pl.col('price') * pl.col('volume')).alias('value'))
    .group_by('symbol')
    .agg(
        pl.col('value').sum().alias('total_value'),
        pl.col('amount').count().alias('trades'),
        pl.col('price').mean().alias('avg_price'),
    )
    .sort('total_value', descending=True)
    .limit(10)
)

# Xem query plan (để debug/optimize)
print(lf.explain())

# THỰC THI - lúc này Polars mới tối ưu và chạy
result = lf.collect()

# Streaming mode - xử lý dữ liệu > RAM
# Dữ liệu được xử lý theo batch, không cần load hết vào RAM
result = lf.collect(streaming=True)

Lazy evaluation tối ưu gì?​

  1. Predicate pushdown: đẩy filter xuống sớm nhất có thể khi đọc file (Parquet)
  2. Projection pushdown: chỉ đọc những cột cần dùng
  3. Constant folding: tính toán biểu thức hằng số trước
  4. Slice pushdown: khi có limit, chỉ đọc số dòng cần
  5. Join reordering: sắp xếp lại thứ tự join cho tối ưu
# Ví dụ: đọc 100GB parquet, lấy top 10
# Polars lazy chỉ đọc ~ vài MB, không load toàn bộ 100GB!
lf = pl.scan_parquet('huge_data/*.parquet')
result = (lf
    .filter(pl.col('date').dt.year() == 2024)
    .group_by('symbol')
    .agg(pl.col('volume').sum())
    .sort('volume', descending=True)
    .limit(10)
    .collect()
)

18. Chuyển Đổi Qua Lại Với Pandas và NumPy​

# Polars -> Pandas
pdf = df.to_pandas()

# Pandas -> Polars
df = pl.from_pandas(pdf)

# Polars -> NumPy
arr = df.to_numpy()

# NumPy -> Polars
df = pl.from_numpy(arr, schema=['A', 'B'])

# Polars -> Arrow Table
table = df.to_arrow()

19. Tips và Best Practices​

19.1 Luôn dùng Expression, tránh map_elements​

# CHẬM
df.with_columns(
    pl.col('name').map_elements(lambda x: x.upper(), return_dtype=pl.String)
)

# NHANH
df.with_columns(
    pl.col('name').str.to_uppercase()
)

19.2 Dùng Lazy mode​

# EAGER - chạy từng bước
df = pl.read_csv('data.csv')
df = df.filter(pl.col('amount') > 100)
df = df.group_by('category').agg(pl.col('amount').sum())

# LAZY - tối ưu toàn bộ rồi mới chạy
result = (pl.scan_csv('data.csv')
    .filter(pl.col('amount') > 100)
    .group_by('category')
    .agg(pl.col('amount').sum())
    .collect()
)

19.3 Đọc file định dạng Parquet​

# Parquet nhanh hơn CSV nhiều lần
# Hỗ trợ predicate pushdown và projection pushdown
df = pl.read_parquet('data.parquet')
# Hoặc lazy
lf = pl.scan_parquet('data.parquet')

19.4 Chọn kiểu dữ liệu nhỏ nhất có thể​

df = pl.DataFrame({
    'age': [25, 30, 35],
    'count': [100, 200, 300],
}, schema={
    'age': pl.Int8,        # -128..127 (thay vì Int64)
    'count': pl.UInt16,    # 0..65535
})

19.5 Dùng streaming cho dữ liệu > RAM​

# Xử lý 500GB CSV không cần đủ RAM
result = (pl.scan_csv('huge.csv')
    .filter(pl.col('date').dt.year() == 2024)
    .group_by('category')
    .agg(pl.col('amount').sum())
    .collect(streaming=True)
)

19.6 Pipe để method chaining sạch​

result = (df
    .pipe(lambda d: d.with_columns(
        pl.col('salary').fill_null(pl.col('salary').mean())
    ))
    .filter(pl.col('age') >= 25)
    .group_by('city')
    .agg(pl.col('salary').mean())
    .sort('salary', descending=True)
)

Tổng kết​

Polars là lựa chọn hàng đầu khi:

  • Dữ liệu lớn (>1GB) và bạn cần tốc độ
  • Pipeline ETL trong production
  • Cần xử lý multi-threaded
  • Làm việc với Parquet/Apache Arrow
  • Cần streaming cho dữ liệu > RAM

Hãy bắt đầu với Lazy mode (scan_csv, scan_parquet) và dùng expression API thay vì map_elements để đạt hiệu năng tối đa.
